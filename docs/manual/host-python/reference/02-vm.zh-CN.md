# VM 句柄

`VMHandle` 是 Python 宿主观察和控制一台 VM 的公开入口。它由[`SericiteEngine.create_root`](01-engine-and-limits.zh-CN.md#sericiteenginecreate_root)返回，与创建它的引擎绑定，不应直接实例化。

脚本内 `VM()` 返回的句柄共享大部分状态和驱动语义，但宿主快照、文件管理和资源计费存在差异。脚本通用契约的权威说明见[脚本 VM 参考](../../scripting/reference/06-vm.zh-CN.md)。

## 状态

| 状态 | 含义 | 是否终态 |
|---|---|---|
| `ready` | 尚未开始或可以继续执行 | 否 |
| `waiting_input` | 等待以后可能到达的输入 | 否 |
| `paused` | 在语句入口断点暂停，执行状态可恢复 | 否 |
| `done` | 当前程序正常完成 | 是 |
| `error` | 当前程序因普通错误终止 | 是 |
| `resource_exhausted` | 当前程序因资源配额耗尽终止 | 是 |
| `terminated` | 被终止或级联销毁终止 | 是 |

空源码在创建后即可处于 `done`。终态不等于句柄失效：仍可读取快照和 stdout、管理断点、取回 VFS 或销毁。

销毁没有可读取的 `disposed` 状态。销毁后，除重复 `dispose()` 外，其他句柄操作报 `runtime_error`。

## VMHandle.run

```python
vm.run(inputs: list[str] | tuple[str, ...] | None = None) -> str
```

驱动目标，直到完成、等待输入、命中断点或失败。返回目标当前保留的累计 stdout，不只是本次调用新增的文本。

`inputs` 中的整批字符串先加入目标输入队列。目标处于 `waiting_input` 时会转为 `ready`；其他状态也可提前预置输入。

- 返回不代表状态一定是 `done`，应通过快照识别 `waiting_input` 或 `paused`。
- `buffer_output=False` 时返回空字符串，输出转发与观察事件仍然发生。
- 脚本错误以 `SericiteError` 向宿主传播，已产生输出不会因此撤回。
- 同一 VM 已在驱动中时拒绝嵌套调度。
- 无效输入值以 `SericiteError` 拒绝，不会把非字符串加入队列。

## VMHandle.exec

```python
vm.exec(source: str) -> str
```

编译并投递新源码，在同一个模块作用域中立即执行，只返回本次投递新增的缓冲输出。

保留模块级变量、函数和 schema、已加载模块缓存、addon、VFS、模块解析根、输入队列、输出配置、断点和累计资源用量。root 的 `argv` 也继续存在。

`exec()` 会丢弃尚未执行完的旧程序，包括从未开始、等待输入或断点暂停的执行状态；旧错误和调试帧栈被替换。需要保留旧程序状态时应先调用 `snapshot()`。不要用 `exec()` 代替输入恢复或断点恢复。

编译先于状态改变：编译失败时，原程序、暂停时的执行状态和断点绑定保持原样。成功投递后，无主路径断点按相同行号绑定新主源码，不命中旧投递遗留的函数。

`terminated`、已取出 VFS 或正在运行的 VM 拒绝投递。`source` 必须是字符串，并遵守与 root 创建相同的 4 MiB UTF-8 源码上限。

## 输入

### VMHandle.feed_input

```python
vm.feed_input(value: str) -> None
```

向目标输入队列加入一行字符串。目标处于 `waiting_input` 时转为 `ready`，但本方法不主动执行目标；之后调用 `run()`、`step()` 或 `step_instruction()` 继续。

### 创建时输入

`create_root(inputs=...)` 和 `input_provider` 的契约见[引擎创建参数](01-engine-and-limits.zh-CN.md#输入与输出)。provider 的暂停与 `input_error` 规则不会改变本节方法的所有权。

## 单步

### VMHandle.step

```python
vm.step() -> dict[str, object]
```

执行一条语句并返回[宿主快照](#快照)。函数调用内部的语句和断点可能影响实际停止位置。目标已处于终态时不推进，只返回快照；目标处于 `paused` 时恢复，当前断点只豁免一次。

### VMHandle.step_instruction

```python
vm.step_instruction() -> dict[str, object]
```

执行一条 Sericite 内部指令并返回宿主快照。终态和断点恢复规则与 `step()` 相同。内部指令是调试粒度，不是脚本源码中的公开运算 API。

## 输出

### VMHandle.stdout

```python
vm.stdout() -> str
```

返回目标当前保留的累计 stdout，不推进执行。`buffer_output=False` 时返回空字符串。

输出缓冲、writer 和观察事件的先后顺序见[执行会话与虚拟 IO](../guides/02-sessions-and-io.zh-CN.md#实时转发输出)及[观察事件](05-observation.zh-CN.md#事件种类)。

## 断点

### VMHandle.add_breakpoint

```python
vm.add_breakpoint(line: int, path: str | None = None) -> None
```

添加语句入口行断点。`line` 必须是大于零的严格整数，`bool` 不被接受；`path` 为 `None` 或按 VFS 规则规范化的逻辑路径。重复添加是空操作。

### VMHandle.remove_breakpoint

```python
vm.remove_breakpoint(line: int, path: str | None = None) -> None
```

删除指定位置。位置不存在时是空操作，参数规则与添加相同。

### VMHandle.breakpoints

```python
vm.breakpoints() -> list[dict[str, object]]
```

按添加顺序返回独立字典，每项形如：

```python
{"line": 2, "path": None}
```

只要 VM 尚未销毁就可以管理断点。宿主断点管理没有目标专属数量上限，也不计入目标脚本资源计量。

### 命中与恢复

- `path=None` 匹配当前主源码及其函数；显式路径匹配目标自己的入口和 import 模块。
- 断点位置同时受目标 VM 和源码身份约束，不误命中其他 VM 授予的外来代码。
- 只有实际语句入口命中；空行、注释、多行语句的非起始行和不产生指令的 `pass` 不命中。
- 命中发生在第一条指令执行前，状态变为 `paused`，不移动 PC，不执行目标的 `except/finally`。
- `run()` 在断点处正常返回，快照的 `breakpoint` 记录实际 `line`、`path`。
- 从 `paused` 调用 `run()` 或单步方法恢复，只豁免当前断点一次；循环再次到达时仍会命中。
- 暂停不向祖先传播。

## 快照

### VMHandle.snapshot

```python
vm.snapshot() -> dict[str, object]
```

返回当前宿主安全快照，不推进执行。快照只含安全副本，不含可操作的 VM 句柄；修改返回值不会修改 VM。

宿主快照是脚本安全视图的严格超集：

| 字段 | 类型 | 含义 |
|---|---|---|
| `state` | `str` | 当前 VM 状态 |
| `last_line` | `int \| None` | 最近执行的逻辑源码行 |
| `next_line` | `int \| None` | 下一条可执行源码行 |
| `locals` | `dict` | 当前用户可见局部值的安全副本 |
| `stdout` | `str` | 当前保留输出 |
| `error` | `dict \| None` | 当前错误的安全诊断 |
| `breakpoint` | `dict \| None` | 暂停时的 `line`、`path` |
| `instruction_count` | `int` | 当前指令与折算工作量 |
| `vm_id` | `int` | 引擎内编号，永不复用 |
| `parent_id` | `int \| None` | 父 VM 的引擎内编号，root 为 `None` |
| `depth` | `int` | 嵌套深度，root 为 0 |
| `child_count` | `int` | 累计创建的直接子 VM 数，销毁子 VM 不会减少 |

`error` 含 `kind`、`message`、`line`、`column`、`frames`。其中 `frames` 是字典列表，每项含 `function` 和 `line`，不是 `SericiteFrame` 对象。调用栈只暴露该快照所属 VM 的安全视图。

复杂值受节点和深度预算约束，循环或重复结构使用占位符。record 以带 `<record>` 标记的安全数据表示，函数、模块和句柄以显示文本表示。快照不包含可继续驱动子 VM 的句柄或内部上下文。

脚本快照只有前八个通用字段，不能取得 `vm_id` 等宿主诊断字段。

## 生命周期

### VMHandle.terminate

```python
vm.terminate() -> None
```

把 `ready`、`waiting_input` 或 `paused` 的目标标记为 `terminated`；其他状态下是静默空操作。

此操作只改变当前目标，不级联终止后代。目标之后仍可快照、读取 stdout 和 `take_fs()`，但不能接受 `exec()`。需要销毁整棵后代树时使用 `dispose()`。

### VMHandle.dispose

```python
vm.dispose() -> None
```

销毁任意状态的目标及其全部存活后代，并释放存活 VM 数量槽位。

- 可在非终态调用，不要求子先父后。
- 正在运行的目标在当前指令安全退出后停止，不执行目标脚本的 `finally`。
- 重复调用是空操作。
- 调用后目标句柄失效，其他方法报 `runtime_error`。
- 不退还已经消耗的累计指令、输出或内存额度。

彻底不可达的 VM 最终也会由 Python GC 回收，包括引用环，但时机不保证。需要确定释放时点时应显式 `dispose()`。观察自动回收的通知时点另见[观察参考](05-observation.zh-CN.md#垃圾回收通知)。

### VMHandle.take_fs

```python
vm.take_fs() -> VFSHandle
```

从终态 VM 原子取出依附的 VFS，返回新的分离句柄。只允许 `done`、`error`、`resource_exhausted` 和 `terminated`；非终态或正在运行时以 `runtime_error` 拒绝。

取出后，原 VM 仍可快照、读取 stdout 和销毁，但失去文件访问能力，不再接受 `exec()`。原 VM 定义的函数也不能继续通过原 VM 访问已经移交的工作区。销毁原 VM 不影响取回的 VFS。

目标没有依附 VFS 时同样拒绝。失败时所有权不变。完整移交规则见[VFS 与文件](03-vfs-and-files.zh-CN.md)。

## 宿主文件管理

宿主 `VMHandle` 还提供 `read_file`、`write_file`、`delete_file`、`rename_file`、`copy_file`、`make_dir`、`delete_dir`、`rename_dir`、`copy_dir`、`list_dir`、`path_exists`，操作该 VM 当前依附的 VFS。

这些方法是可信宿主管理通道，不是脚本内 VM 句柄的公开代理。签名和限制统一见[VFS 与文件](03-vfs-and-files.zh-CN.md#文件与目录方法)。

## 宿主管理与脚本计量

宿主的 `feed_input()`、断点管理、`VMHandle`/`VFSHandle` 文件操作、stdout/快照读取和 `dispose()` 不计入脚本资源计量。资源自身的文件数量、单文件字节、总存储量和输出字节限制仍然有效。

`run()`、`exec()`、`step()` 和 `step_instruction()` 执行的实际 VM 指令及动态操作始终受 VM 配额约束。宿主管理免费不代表脚本执行免费。
