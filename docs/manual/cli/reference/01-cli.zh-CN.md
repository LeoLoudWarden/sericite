# 命令行参考

本文定义 `sericite` 与 `python -m sericite` 的共同行为，供需要核对参数、配置、诊断和退出行为时使用。按任务组织的示例见[命令行指南](../README.zh-CN.md#指南)。

## 命令与参数

```text
sericite [-h] [--version] [--addons FILE]
         [(SOURCE_FILE | -c SOURCE) [ARG ...]]
```

| 参数 | 含义 |
|---|---|
| `-h`, `--help` | 显示帮助并退出 |
| `--version` | 显示运行时版本并退出 |
| `SOURCE_FILE` | 读取并运行 UTF-8 源文件及其静态可达模块；`-` 表示从 stdin 读取完整源码 |
| `-c SOURCE`, `--command SOURCE` | 直接执行源码字符串 |
| `ARG ...` | 传给脚本的参数，不再由命令行解释 |
| `--addons FILE` | 从可信 Python 文件调用 `configure()`，配置入口程序 |

省略 `SOURCE_FILE` 和 `-c` 时进入 REPL。`.sericite` 是约定后缀，命令行不强制检查后缀。文件路径按当前工作目录解析。

CLI 选项放在源码入口之前。入口之后的内容全部属于脚本，包括 `--flag` 和单独的 `--`。在入口前写 `--` 可以显式结束 CLI 选项，也可用它传入以横线开头的文件名；这个 `--` 由 CLI 消费，不进入 `argv`。

### `argv`

入口程序启动时带有一个字符串列表变量 `argv`：

| 入口 | 初始值 |
|---|---|
| 文件模式 | `[SOURCE_FILE, *ARG]`，保留命令中写下的入口路径 |
| `-c` 模式 | `["-c", *ARG]` |
| stdin 源码模式 | `["-", *ARG]` |
| REPL | `[]` |

`argv` 是普通模块变量，可以读取、修改或重绑定，并在 REPL 的多次输入之间保留。子 VM 不隐式继承它。

### 源码编码

主文件、静态可达模块和 stdin 源码按 UTF-8 解码，并忽略开头可选的一个 UTF-8 BOM；诊断中的行号和列号按忽略 BOM 后的文本计算。

## 多文件项目

文件模式以入口文件所在目录为项目根。CLI 把入口文件及静态 import 可达的 `.sericite` 文件复制到入口 VM 的虚拟文件系统（VFS），保持相对于项目根的路径，然后执行入口。

项目加载遵循以下规则：

- 只复制静态 import 可达的源码，不复制整个目录。未引用的源码和数据文件不会因此进入 VFS。
- 启动扫描会收集语法中的 import，包括函数和条件分支里的 import；实际模块仍在执行到 import 语句时加载。
- 符号链接解析后越出入口目录的候选文件不会加载。
- 实际 import 只读取 VFS，不会回到真实磁盘寻找模块。运行期间修改虚拟文件也不会写回项目目录。
- 未执行到的 import 保持惰性；缺失、非法或循环模块在实际执行到时按语言规则报错。
- `-c`、stdin 和 REPL 不扫描当前目录，只从已有 VFS 导入；可以通过 addon 的 `files` 预置模块。

模块解析和导入语义见[语言与模块](../../scripting/reference/01-language.zh-CN.md#模块与包)。

文件入口先写入项目快照，再写入 addon 的 `files`。两者包含相同虚拟路径时，配置内容覆盖项目快照。

## addon 配置

`--addons FILE` 指定的 Python 文件必须定义可调用的无参数 `configure()`。加载文件会执行其 Python 顶层代码，随后 CLI 调用一次 `configure()`。

`configure()` 必须返回 dict。以下三个键都可省略，空 dict 等价于不配置：

| 键 | 类型与作用 |
|---|---|
| `addons` | `dict[str, callable]`；以键为导入名，向入口程序授予 Python 可调用对象 |
| `limits` | `SericiteLimits`；入口程序的整套配额配置 |
| `files` | `dict[str, str]`；运行前写入 VFS 的虚拟路径与纯文本内容 |

未知键、缺少可调用的 `configure()`、返回非 dict 或字段类型错误都会使启动失败。addon 的导入名仍按语言规则校验；`files` 仍受文件数、单文件大小和总存储限制。

脚本通过 `from __addon__ import name` 使用授予的函数。每个需要 addon 的源码模块都要自行导入，见[`__addon__`：授予能力入口](../../scripting/reference/01-language.zh-CN.md#__addon__授予能力入口)。

启动顺序固定为：

```text
读取源码并建立项目快照
→ 执行 Python 配置文件与 configure()
→ 创建入口 VM 并编译入口源码
→ 写入项目文件和配置 files
→ 执行 Sericite 程序
```

配置文件可用 `__file__` 定位并读取自己的资源，再把文本放进 `files`。它不是 Sericite 模块，所在目录不必成为 Python 包。CLI 不提供额外的 Sericite 模块搜索路径。

配置文件只能准备入口程序，不能接管 REPL 循环或逐步控制执行。需要由既有应用管理 VM 生命周期时，应使用 Python 嵌入 API，而不是扩展 CLI 配置。

### 数据与信任边界

> **addon 配置文件拥有完整宿主权限。像运行任何 Python 文件一样信任它。**

配置文件及其授予的 Python 函数可以 import 第三方库、读取环境变量和真实磁盘、访问网络。它们运行在 Sericite 沙箱之外，其 CPU、内存、阻塞和外部副作用不受引擎配额约束。只应由操作者选择配置文件，不要让模型或 Sericite 源码决定加载哪一个。

宿主与脚本之间的参数和返回值会双向深拷贝，只允许 `None`、布尔值、数值、字符串，以及由这些纯数据递归组成的 list、dict 和 tuple。任意 Python 对象不会因为被 addon 返回就进入脚本。

引擎保证未授予的能力不可达，但不替能力实现者判断操作是否安全。执行不可信代码前，应阅读[安全模型](../../../security.zh-CN.md)，并为 addon 自行校验参数、限制资源；对真正的对抗性代码，还需要独立的操作系统级隔离。

## REPL

不带 `SOURCE_FILE` 或 `-c` 时，CLI 创建持久会话并进入交互循环：

- `>>>` 等待新输入，`...` 等待多行语句完成；空输入不执行。
- 变量、函数、schema、已导入模块和虚拟文件跨输入保留。
- 单个表达式用 `repr` 回显非 `None` 的结果；其他语句只显示自身产生的输出。`_` 保存最近一次表达式结果。
- 单次编译或运行错误写入 stderr，随后可以继续输入；已经建立的会话状态不会因此整体重建。
- addon 配置或入口 VM 的启动失败仍使命令以状态码 1 退出。
- EOF 正常结束 REPL，退出码为 0。

REPL 不提供历史记录、自动补全、复杂行编辑或调试命令。

## 输入与输出

CLI 标准流沿用运行环境的编码，不主动重新配置。Windows 等非 UTF-8 环境可在当前 PowerShell 会话设置 `$env:PYTHONUTF8 = "1"`；源文件的 UTF-8 读取规则不受此设置影响。

- 脚本 `input()` 从 stdin 逐行读取并去掉行尾换行符；EOF 抛出可捕获的 `input_error`。
- `sericite -` 先消费全部 stdin 作为源码，再开始执行，因此源码中的 `input()` 无法继续从同一 stdin 读取数据。
- REPL 命令与脚本 `input()` 共用 stdin。一条命令调用 `input()` 后，接下来的一行先作为脚本数据。
- 入口程序每次 `print()` 都立即写入并刷新 stdout，包括 `end=""` 的无换行输出。CLI 不额外保留一份程序输出缓冲。
- 只有入口程序的输出会自动连接到宿主 stdout。子 VM 输出由父程序通过 VM 接口显式取得或转发，见 [VM 参考](../../scripting/reference/06-vm.zh-CN.md)。

下游 stdout 管道关闭表示外部消费者已经结束：CLI 停止当前执行，丢弃后续输出并安静退出 0。这不是脚本错误，也不保证执行 Sericite 的 `finally` 块。

## 错误诊断

编译和运行错误写入 stderr；程序失败前已经写入 stdout 的内容不会丢失。错误首行给出源码位置、错误 kind 和消息；存在调用栈时，各帧从调用方指向实际错误点，并使用定义该代码的源码位置。

| 来源 | 诊断中的名称 |
|---|---|
| 入口文件 | 命令行中给出的路径 |
| 项目导入模块 | `/pkg/mod.sericite` 这样的虚拟路径 |
| `-c` 命令字符串 | `<command>` |
| stdin 源码和 REPL 输入 | `<stdin>` |

入口文件在启动阶段发现的语法错误只有单行诊断，没有调用栈。导入模块的错误在实际执行 import 时发生，可以带调用栈，也可以按语言规则捕获。

REPL 中，各帧映射到定义该代码的输入。无法确定来源时显示 `<sericite>` 和 `line ?`；其他工作空间定义的代码不披露行号，显示为 `line ?`。

脚本异常和错误 kind 见[错误与异常](../../scripting/reference/05-errors.zh-CN.md)。

## 退出码

| 退出码 | 含义 |
|---:|---|
| 0 | 程序正常完成、REPL 以 EOF 结束，或下游 stdout 管道关闭 |
| 1 | 文件或 addon 配置读取与校验失败、入口 VM 启动失败、一次性执行失败 |
| 2 | 命令行用法错误，例如无法识别的 CLI 选项 |

一次性程序未捕获 `input_error` 时以 1 退出；REPL 中普通的单次输入错误不会结束会话，也不会因此使整个进程以 1 退出。脚本参数位于入口之后，即使看起来像 CLI 选项，也不会因此产生退出码 2。

`KeyboardInterrupt`、`SystemExit` 等进程级事件不当作普通脚本或配置错误吞掉。
