# 独立运行空间

Sericite 提供内置的 `VM` 功能，允许你在脚本中把一段源码作为独立程序运行。但在此之前，你需要先了解**理想程序**的概念，Sericite 的设计理念围绕着这一点。

## 理想程序

从计算机的基本抽象开始，一个程序在一个空间中运行，这个空间需要满足：

| 要素 | 在 Sericite 中的体现 |
|---|---|
| 程序 | Sericite 源码 |
| 内存 | 变量、函数、调用帧和模块环境等运行状态 |
| 输入输出 | 程序与外部交换数据的通道 |
| 外存 | 以路径组织、可反复读写的文本工作区 |

## 一个独立子程序

下面的程序在运行时，动态地把一段源码作为另一个独立的程序运行，并提供一行输入：

```python
source = """
name = input()
message = "hello " + name
write_file("/message.txt", message)
print(read_file("/message.txt"))
"""

program = VM(source)
output = program.run(["world"])
print(output, end="")
print("parent copy:", path_exists("/message.txt"))
program.dispose()
```

预期输出：

```text
hello world
parent copy: False
```

## 虚拟机

每个虚拟机都是一个独立的运行空间，包含**理想程序**的四要素。Sericite 允许你通过 `VM` 在运行时动态地创建、驱动和调试子程序。这便是 Sericite 的**玻璃箱哲学**：所有程序都是透明的、可被观察的、影响可控的。

### 移交工作区

前面的示例中，子程序写入的 `/message.txt` 并没有出现在父程序的工作区。

如果需要预先放入文件，或者在子程序结束后取回它生成的文件，可以显式移交一个工作区：

```text
准备工作区 → 移入子程序 → 子程序读写文件 → 取回工作区
```

下面的子程序读取 `/input.txt`，把处理结果写入 `/result.txt`：

```python
source = """
text = read_file("/input.txt")
write_file("/result.txt", "received: " + text)
print("finished")
"""

workspace = VFS()                              # 创建一个独立工作区
workspace.write_file("/input.txt", "hello")    # 可以向其中写入文件
workspace.write_file("/main.sericite", source)

program = VM(entry_file="/main.sericite", fs=workspace)
print(program.run(), end="")

workspace = program.take_fs()                  # 取回工作区
print(workspace.read_file("/result.txt"))      # 依然可以读取
```

预期输出：

```text
finished
received: hello
```

`VFS()` 创建一个独立工作区。创建 VM 时，`fs=workspace` 将这个工作区移交给子程序，`entry_file="/main.sericite"` 指定从其中的哪个文件开始执行。此后，子程序中的 `read_file()` 和 `write_file()` 都作用于这个工作区；运行期间，工作区由 `program` 独占。程序结束后，可用 `take_fs()` 取回。

前面的 `VM(source)` 没有指定 `fs=...`，则默认创建一个空的 `VFS()`。

### 授予能力

除了准备工作区，还可以向子程序提供函数。前面已经介绍过，脚本通过 `from __addon__ import ...` 导入运行环境提供的扩展能力。创建 VM 时，可使用 `addons` 决定这个入口中有哪些名字。

下面的代码演示如何把 `double` 函数提供给子程序：

```python
def double(number):
    return number * 2

source = """
from __addon__ import double
print(double(21))
"""

program = VM(source, addons={"double": double})
print(program.run(), end="")
```

预期输出：

```text
42
```

`addons` 是一个字典：键是子程序使用的导入名，值是父程序当前作用域中的函数。这里的 `{"double": double}` 表示以 `double` 这个名字提供右侧的函数。键使用字符串，因此提供给子程序的名字可以与父程序中的函数名不同。

### 等待输入后继续

前面的 `run(["world"])` 展示了一次性提供输入。如果暂时只知道一部分输入，或者希望根据子程序的进度决定下一行输入，就需要使用如下形式：

```python
vm = VM("""
a = input()
b = input()
print(a + b)
""")

vm.run(["2"])
print(vm.snapshot()["state"])

vm.feed_input("3")
print(vm.run(), end="")
```

预期输出：

```text
waiting_input
23
```

`run()` 返回不一定代表程序已经结束。输入不足时会保留现场，之后可以继续驱动它。

### 继续执行后续代码

`run()` 执行创建 VM 时提供的源码。之后还可以通过 `exec()` 向同一个 VM 交付新的源码：

```python
def forward(text):
    print("vm-output:", text, end="")

program = VM("x = 40", output_writer=forward)
program.run()                       # 执行 x = 40
program.exec("x += 2")              # 修改同一个运行空间中的 x
program.exec('print("answer:", x)')
```

预期输出：

```text
vm-output: answer: 42
```

上面的三次操作都发生在同一个运行空间中：创建时的源码建立了 `x`，第一次 `exec()` 修改它，第二次 `exec()` 再读取它。

示例还设置了 `output_writer`。子程序每次调用 `print()`，都会把这次产生的文本交给 `forward`，可以立即处理输出，而不必等到 `run()` 或 `exec()` 返回。

`run()` 和 `exec()` 仍然会返回输出文本；上例没有再次打印返回值，以免同一份输出显示两次。

### 观察执行过程

除了使用 `run()` 连续执行，还可以逐语句推进子程序，并在每一步查看它的运行现场：

```python
program = VM("""
x = 10
x += 5
print(x)
""")

snapshot = program.step()
print(snapshot["state"], snapshot["locals"])          # ready

snapshot = program.step()
print(snapshot["state"], snapshot["locals"])          # ready

snapshot = program.step()
print(snapshot["state"], snapshot["stdout"], end="")  # done
```

预期输出：

```text
ready {'x': 10}
ready {'x': 15}
done 15
```

`snapshot()` 返回只读快照，包含：

- `state` 表示当前状态；
- `locals` 当前可见的局部变量；
- `stdout` 子程序产生的累积输出。
