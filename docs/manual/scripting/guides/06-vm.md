# Isolated execution spaces

Sericite provides a built-in `VM` capability that lets you run a piece of source as an independent program inside a script. Before that, you need to understand the concept of an **ideal program** — Sericite's design ideas revolve around it.

## The ideal program

Starting from the basic abstraction of a computer, a program runs in a space, and that space needs:

| Element | Its form in Sericite |
|---|---|
| Program | Sericite source |
| Memory | Runtime state such as variables, functions, call frames, and module environments |
| Input/output | Channels through which the program exchanges data with the outside |
| External storage | A text workspace organized by paths that can be read and written repeatedly |

## An independent child program

The following program dynamically runs a piece of source as another independent program at runtime and provides one line of input:

```python
source = """
name = input()
message = "hello " + name
write_file("/message.txt", message)
print(read_file("/message.txt"))
"""

program = VM(source)
output = program.run(["world"])
print(output, end="")
print("parent copy:", path_exists("/message.txt"))
program.dispose()
```

Expected output:

```text
hello world
parent copy: False
```

## Virtual machines

Every virtual machine is an independent execution space containing the four elements of the **ideal program**. Sericite lets you dynamically create, drive, and debug child programs through `VM`. This is Sericite's **glass-box philosophy**: all programs are transparent, observable, and controllable in their impact.

### Transferring a workspace

In the earlier example, the `/message.txt` written by the child program did not appear in the parent program's workspace.

If you need to put files in beforehand, or take back the files it generates after the child program ends, you can explicitly transfer a workspace:

```text
prepare a workspace → move into the child program → the child program reads and writes files → take the workspace back
```

The following child program reads `/input.txt` and writes the processed result into `/result.txt`:

```python
source = """
text = read_file("/input.txt")
write_file("/result.txt", "received: " + text)
print("finished")
"""

workspace = VFS()                              # create an independent workspace
workspace.write_file("/input.txt", "hello")    # you can write files into it
workspace.write_file("/main.sericite", source)

program = VM(entry_file="/main.sericite", fs=workspace)
print(program.run(), end="")

workspace = program.take_fs()                  # take the workspace back
print(workspace.read_file("/result.txt"))      # still readable
```

Expected output:

```text
finished
received: hello
```

`VFS()` creates an independent workspace. When creating the VM, `fs=workspace` hands this workspace to the child program, and `entry_file="/main.sericite"` specifies which file in it to start from. After that, `read_file()` and `write_file()` in the child program all operate on this workspace; while it runs, the workspace is held exclusively by `program`. After the program ends, you can take it back with `take_fs()`.

The earlier `VM(source)` did not specify `fs=...`, so an empty `VFS()` is created by default.

### Granting capabilities

Besides preparing a workspace, you can also provide functions to a child program. As introduced earlier, a script imports the extension capabilities provided by the runtime through `from __addon__ import ...`. When creating a VM, you can use `addons` to decide which names exist in this entry.

The following code shows how to provide a `double` function to the child program:

```python
def double(number):
    return number * 2

source = """
from __addon__ import double
print(double(21))
"""

program = VM(source, addons={"double": double})
print(program.run(), end="")
```

Expected output:

```text
42
```

`addons` is a dictionary: the keys are the import names the child program uses, and the values are functions in the parent program's current scope. Here `{"double": double}` means provide the function on the right under the name `double`. Because the keys are strings, the name provided to the child program can differ from the function's name in the parent program.

### Waiting for input and continuing

The earlier `run(["world"])` showed providing all input at once. If you only know part of the input for now, or want to decide the next line of input based on the child program's progress, use the following form:

```python
vm = VM("""
a = input()
b = input()
print(a + b)
""")

vm.run(["2"])
print(vm.snapshot()["state"])

vm.feed_input("3")
print(vm.run(), end="")
```

Expected output:

```text
waiting_input
23
```

A `run()` return does not necessarily mean the program has ended. When input runs short, the state is preserved and you can keep driving it later.

### Running more code

`run()` executes the source provided when the VM was created. After that, you can deliver new source to the same VM with `exec()`:

```python
def forward(text):
    print("vm-output:", text, end="")

program = VM("x = 40", output_writer=forward)
program.run()                       # executes x = 40
program.exec("x += 2")              # modify x in the same execution space
program.exec('print("answer:", x)')
```

Expected output:

```text
vm-output: answer: 42
```

The three operations above all happen in the same execution space: the source at creation establishes `x`, the first `exec()` modifies it, and the second `exec()` reads it again.

The example also sets `output_writer`. Every time the child program calls `print()`, the text produced this time is handed to `forward`, so output can be handled immediately without waiting for `run()` or `exec()` to return.

`run()` and `exec()` still return the output text; the example does not print the return values again, to avoid showing the same output twice.

### Observing execution

Besides continuous execution with `run()`, you can also advance the child program statement by statement and inspect its execution state at each step:

```python
program = VM("""
x = 10
x += 5
print(x)
""")

snapshot = program.step()
print(snapshot["state"], snapshot["locals"])          # ready

snapshot = program.step()
print(snapshot["state"], snapshot["locals"])          # ready

snapshot = program.step()
print(snapshot["state"], snapshot["stdout"], end="")  # done
```

Expected output:

```text
ready {'x': 10}
ready {'x': 15}
done 15
```

`snapshot()` returns a read-only snapshot containing:

- `state`, the current state;
- `locals`, the currently visible local variables;
- `stdout`, the child program's accumulated output.
