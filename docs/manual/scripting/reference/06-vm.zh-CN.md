# VM

`VM` 在脚本中创建一个独立的 Sericite 运行环境。子环境不继承父环境的局部变量、模块缓存、输入、输出或文件。

VM 不是一次性的，`run()`、输入等待、断点暂停、单步和多次 `exec()` 都驱动同一个 VM，模块级名字和资源账持续存在。需要全新环境时应创建另一台 VM。

## 构造

```text
VM(source, ...) -> VM
VM(source=source, ...) -> VM
VM(entry_file=path, fs=workspace, ...) -> VM
```

`source` 与 `entry_file` 必须恰好选择一种：

- `source` 是源码字符串，模块从工作区根解析。
- `entry_file` 是工作区中的入口文件路径，必须同时提供 `fs`。创建时读取并编译入口，模块从入口所在目录解析。

两种来源都缺失、同时提供或类型错误时报 `type_error`。入口文件必须显式配合分离 VFS；入口读取或编译失败不会消费该 VFS。

未提供 `fs` 时创建空白 VFS。提供时，成功创建会把分离工作区排他移入新 VM，原句柄失效；详见 [VFS](07-vfs.zh-CN.md)。

### 非配额选项

| 选项 | 默认 | 契约 |
|---|---|---|
| `fs` | `None` | 分离 VFS；成功后移动给子 VM |
| `addons` | `None` | 字符串到函数的字典，经 `__addon__` 授予 |
| `output_writer` | `None` | 每次子 VM `print()` 后调用的函数 |
| `buffer_output` | `True` | 是否保留 stdout；必须严格为 `bool` |

未知选项、无效的 addon 表、writer 或选项类型报 `type_error`。

## 状态

| 状态 | 含义 | 是否终态 |
|---|---|---|
| `ready` | 尚未开始或可以继续执行 | 否 |
| `waiting_input` | 正在等待以后可能到达的输入 | 否 |
| `paused` | 在语句入口断点暂停，现场可恢复 | 否 |
| `done` | 当前程序正常执行完成 | 是 |
| `error` | 当前程序因普通错误终止 | 是 |
| `resource_exhausted` | 当前程序因资源配额耗尽终止 | 是 |
| `terminated` | 被 `terminate()` 或级联销毁终止 | 是 |

销毁后 VM 句柄失效，不再提供可读取的 `disposed` 状态；除重复 `dispose()` 外，其他方法报 `runtime_error`。

终态不等于句柄失效。终态 VM 仍可快照、读取 stdout、取回 VFS 或销毁。除 `terminated`、已取出 VFS 和正在运行外，其他状态通常可接受 `exec()`，但耗尽的配额仍可能拒绝后续工作。

## 驱动方法

### `VM.run`

```text
vm.run() -> str
vm.run(inputs) -> str
```

驱动目标，直到完成、等待输入、命中断点或失败。返回目标当前保留的 stdout 字符串。

`inputs` 必须是字符串列表或元组。整批验证后加入目标输入队列；目标处于 `waiting_input` 时会被唤醒。也可以通过 `feed_input()` 逐行提供。

- 返回不保证状态是 `done`，应通过快照判断 `waiting_input` 或 `paused`。
- `run()` 返回累计保留输出，不只是本次调用新增的文本。
- 目标发生错误时按原 kind 向控制方传播；可捕获错误由控制方正常捕获。
- 子 VM 的 `resource_exhausted` 可以被仍存活的父 VM 捕获；父 VM 自身或祖先的资源耗尽不能由父 VM 自己捕获。
- `buffer_output=False` 时不保留输出，因此返回空字符串，但 writer 转发仍发生。

### `VM.exec`

```text
vm.exec(source) -> str
```

编译并投递新源码，在同一个模块作用域中执行。只返回本次投递新增的缓冲输出。

保留的内容：模块级变量、函数和 schema、已导入模块缓存、addon、VFS、模块解析根、输入队列、输出配置、断点和累计资源账。

尚未执行完的旧程序会被丢弃，包括从未开始、等待输入或断点暂停的现场；旧错误和调试帧栈被替换。需要旧现场时应先调用 `snapshot()`。

编译先于状态改变。编译失败时，原程序、暂停现场和断点绑定保持原样。成功投递后，无主路径断点按相同行号绑定新主源码，不命中旧投递遗留的函数。

`terminated`、已取出 VFS 或正在被驱动的 VM 拒绝投递。`source` 必须是字符串。

### `VM.feed_input`

```text
vm.feed_input(value) -> None
```

向目标输入队列加入一行字符串。目标处于 `waiting_input` 时会转为 `ready`，但本方法不主动执行目标；之后调用 `run()` 或单步方法继续。

### `VM.step`

```text
vm.step() -> dict
```

执行一条语句并返回安全快照。函数调用内部的语句和断点可能影响实际停止位置。目标已处于终态时不推进，只返回快照。目标处于 `paused` 时恢复执行，当前断点只豁免一次。

### `VM.step_instruction`

```text
vm.step_instruction() -> dict
```

执行一条 Sericite 内部指令并返回安全快照。终态和断点恢复规则与 `step()` 相同。内部指令是调试粒度，不是脚本源码中的公开运算符 API。

### `VM.snapshot`

```text
vm.snapshot() -> dict
```

返回当前安全快照，不推进执行。字段结构见[快照](#快照)。

### `VM.stdout`

```text
vm.stdout() -> str
```

返回目标当前保留的累计 stdout，不推进执行。`buffer_output=False` 时返回空字符串。

### `VM.terminate`

```text
vm.terminate() -> None
```

把 `ready`、`waiting_input` 或 `paused` 的目标标记为 `terminated`。其他状态下是静默空操作。

目标之后可快照和 `take_fs()`，但不能接受 `exec()`。`terminate()` 只改变这一台目标的状态；需要销毁整棵后代树并释放资源时使用 `dispose()`。

### `VM.dispose`

```text
vm.dispose() -> None
```

销毁任意状态的目标及其全部存活后代，并释放它们占用的存活 VM 数量槽位。

- 可在非终态调用，不要求子先父后。
- 正在运行的目标在当前指令安全退出后停止，不执行目标脚本的 `finally`。
- 重复调用是空操作。
- 调用后目标句柄失效，其他方法报 `runtime_error`。
- 不退还已经消耗的累计指令、输出或内存额度。

执行销毁本身需要资源；资源不足时，`dispose()` 会在实际注销前失败。彻底不可达的 VM 最终也会自动回收，包括循环引用，但时机不保证。需要确定释放时点时应显式 `dispose()`。

### `VM.take_fs`

```text
vm.take_fs() -> VFS
```

从终态 VM 原子取出依附的 VFS，返回新的分离句柄。只允许 `done`、`error`、`resource_exhausted` 和 `terminated`；`ready`、`waiting_input`、`paused` 或正在运行时拒绝。

放弃等待中的会话可先 `terminate()` 再取出。取出后：

- 原 VM 仍可快照、读取 stdout 和销毁；
- 原 VM 失去文件访问能力，不再接受 `exec()`；
- 原 VM 定义的函数，即使已经授予其他 VM，也不能再通过原 VM 的文件函数访问已经移交的工作区；
- 销毁原 VM 不影响取回的 VFS。

目标没有依附 VFS 或状态不允许时报 `runtime_error`。失败时所有权不变。

## 输出转发与缓冲

每台 VM 有独立输出配置。父程序可显式配置 `output_writer`：

```python
def forward(text):
    print(text, end="")

program = VM("print(\"live\")", output_writer=forward)
program.run()
```

每次目标 `print()` 完成输出处理、计量和可选缓冲后，writer 收到一个字符串，包含本次调用的分隔符和 `end`。

- writer 遵循 addon 的定义方环境规则；调用父级 `print()` 可沿父级输出链继续转发。
- 返回值被忽略。
- writer 错误在触发它的目标 `print()` 处传播。
- writer 必须同步完成；试图通过 `input()` 暂停会在该 `print()` 处报 `runtime_error`。

默认 `buffer_output=True`，`run()`、`exec()`、`stdout()` 和快照保留输出。设为 `False` 后仍计量并转发，但缓冲视图为空。配置跨 `exec()` 保留。

## 断点

### `VM.add_breakpoint`

```text
vm.add_breakpoint(line, path=None) -> None
```

添加语句入口行断点。`line` 必须是大于零的严格整数；`path` 为 `None` 或按 VFS 规则规范化的逻辑路径。重复添加是空操作。

`path=None` 匹配当前主源码及其函数。显式路径匹配目标自己的入口文件和 import 模块，不匹配其他 VM 授予的外来代码。

### `VM.remove_breakpoint`

```text
vm.remove_breakpoint(line, path=None) -> None
```

删除指定位置。位置不存在时是空操作，参数规则与添加相同。

### `VM.breakpoints`

```text
vm.breakpoints() -> list
```

按添加顺序返回纯数据字典列表，每项为：

```python
{"line": 2, "path": None}
```

只要 VM 尚未销毁就可管理断点。没有目标专属断点数量上限，但存储和方法调用仍消耗控制方的一般资源。

### 命中与恢复

只有实际语句入口可命中：空行、注释、多行语句的非起始行和不产生指令的 `pass` 不命中；一行多条有指令的语句可分别命中。

命中发生在第一条指令执行前：

- 状态变为 `paused`，PC、局部变量、调用帧和 stdout 保留。
- `run()` 正常返回，不抛异常，不执行目标的 `except/finally`。
- 快照的 `breakpoint` 字段记录实际位置。
- 从 `paused` 调用 `run()`、`step()` 或 `step_instruction()` 恢复，只豁免当前断点一次；循环再次到达时仍会命中。
- 暂停不向祖先传播。

## 快照

`step()`、`step_instruction()` 和 `snapshot()` 返回以下固定字段：

| 字段 | 类型 | 含义 |
|---|---|---|
| `state` | `str` | 当前 VM 状态 |
| `last_line` | `int` 或 `None` | 最近执行的逻辑源码行 |
| `next_line` | `int` 或 `None` | 下一条可执行源码行 |
| `locals` | `dict` | 当前用户可见局部值的安全副本 |
| `stdout` | `str` | 当前保留输出 |
| `error` | `dict` 或 `None` | 当前错误的安全诊断 |
| `breakpoint` | `dict` 或 `None` | 暂停时命中的 `line`、`path` |
| `instruction_count` | `int` | 当前指令与折算工作量账 |

`error` 含 `kind`、`message`、`line`、`column`、`frames`。`frames` 是字典列表，每项含 `function` 和 `line`。跨 VM 只暴露当前目标自己的安全调用栈。

复杂值受节点和深度预算约束，循环或重复结构使用占位符。record 以带 `<record>` 标记的安全数据表示，函数、模块和句柄以显示文本表示。快照不包含可继续驱动子 VM 的句柄。

## 配额

构造器的配额关键字与下表一一对应：

| 选项 | 默认值 | 限制对象 |
|---|---:|---|
| `max_instructions` | 1,000,000 | 指令及折算工作量 |
| `max_output_bytes` | 1,048,576 | stdout 的 UTF-8 字节数 |
| `max_frames` | 100 | 调用帧数 |
| `max_list_size` | 100,000 | 单列表/元组槽位数 |
| `max_dict_size` | 100,000 | 单字典项数 |
| `max_string_bytes` | 1,048,576 | 单字符串字符数，名称保留历史字节叫法 |
| `max_int_bits` | 4096 | 整数位宽 |
| `max_total_bytes` | 67,108,864 | 近似内存总账高水位 |
| `max_descendant_vms` | 1000 | 单台 VM 的整棵存活后代数，不含自身 |
| `max_vm_depth` | 8 | VM 嵌套深度 |
| `max_fs_files` | 1000 | 文件操作可扩张到的 VFS 文件总数 |
| `max_fs_file_bytes` | 1,048,576 | 可写入或复制的单文件 UTF-8 字节数 |
| `max_fs_storage_bytes` | 67,108,864 | 可扩张到的 VFS 近似总存储量 |

VM 再创建子 VM 时只能收紧继承上限，不能放宽：

- 只有 `max_instructions`、`max_output_bytes`、`max_total_bytes` 接受 `-1`，表示本层不设上限。
- 请求 `-1` 时继承祖先的有效有限上限；只有所有相关层级都无限时才无限。
- 其他配额必须是非负有限整数，不接受 `-1`。
- 把 `max_descendant_vms=0` 可禁止该 VM 创建任何后代，不影响父级创建它。
- 子 VM 的指令、内存和创建消耗也计入相关祖先；有限祖先始终是硬上限。
- 无限配额只取消上限检查，不停止记录用量。

默认值用于开发调试，不是运行不可信代码的安全建议。控制方应按任务显式收紧配额。

三个文件限制是 VM 对操作的约束，不随 VFS 携带。实际调用链共同收紧；约束拒绝变更时使用 `file_limit_error`，与执行账户耗尽的 `resource_exhausted` 不同，见[文件限制](04-files.zh-CN.md#文件限制与错误恢复)。

## addon 授予

```text
VM(source, addons={"public_name": function}) -> VM
```

字典值可以是当前 VM 定义的函数或已持有的被授予函数。键是合法且不以 `__` 开头的标识符，可以与内建同名。若直接导入会重绑定本地内建，接收方应使用导入别名。

子模块必须显式导入：

```python
def double(value):
    return value * 2

program = VM(
    "from __addon__ import double\nprint(double(21))",
    addons={"double": double},
)
print(program.run(), end="")
program.dispose()
```

```text
42
```

被授予的 Sericite 函数：

- 保留定义方模块变量、闭包和已授予环境；
- 函数内的 `print`、文件函数、import 和 `VM()` 仍使用定义该函数的程序环境；
- 调用同时受定义方与调用方资源限制；
- record 跨 VM 按引用共享，字段契约继续有效；
- 参数名可用于接收方的关键字调用，但错误文本不会泄露定义方内部名字和源码行号；
- 定义该函数的 VM 被销毁后，即使函数已经传到其他 VM，调用它也会报 `runtime_error`。

授予函数就是授予它可访问的环境和能力，包括闭包中捕获的 VM 句柄及其控制权限。只授予子程序确实需要的函数。
